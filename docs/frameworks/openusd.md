## What and why

OpenUSD (Universal Scene Description) is the open scene-description system that Kit, Isaac Sim, ovrtx, Newton and the
Omniverse validators all read. PitStudio authors its scenes with **`usd-core`**, the pure-Python build of OpenUSD.
That build has no imaging or Hydra plug-ins [1], which is exactly what a headless, CI-testable scene generator needs.

Why it was chosen:

- **One scene, many engines.** A USD stage written once opens unchanged in Isaac Sim, ovrtx, Kit and Newton, so every
  RTX render, sensor scan and physics run sees the same geometry and the same semantic labels.
- **Composition fits mining.** Sublayers (terrain, design, fleet, animation, lights) and variant sets (pushback phase,
  weather, time of day, level of detail) map one-to-one onto how a pit is planned and reviewed [2].
- **Schemas we need exist:** UsdPhysics for rigid bodies, joints and articulations, UsdSemantics
  (`SemanticsLabelsAPI`, since 24.11) for the labels Replicator turns into ground truth, and UsdPreviewSurface for
  materials that survive the trip to glTF [3][4][5].
- **It runs on the apps' Python.** `usd-core` added Python 3.14 wheels in 26.05 and ships them for Windows, Linux and
  macOS [1][6].

Rejected alternatives:

| Alternative | Why not |
|---|---|
| three.js `USDLoader` as the web delivery path | It reads USDA, USDC and USDZ but not sublayers, inherits, `PointInstancer` or physics [7] |
| `usd2gltf` | Last release 2023-02-23, no instancing [8] |
| Adobe USD file-format plug-ins | Must be built from source against USD 23.08–25.11; no wheels for 26.x [9] |
| A USD-WASM viewer on the public site | The known viewer is non-commercial and needs cross-origin isolation headers that GitHub Pages cannot send [10] |

## How PitStudio uses it

The scene pipeline is pure Python (stages in [Studio stages](../pipelines/studio-stages.md)):

1. `st10_terrain`: crop the lidar or DEM to an area of interest, grid it, and mesh it into adaptive levels of detail.
2. `st20_pit_design`: pit shells, benches, berms, ramps and pushbacks from design code.
3. `st30_assets`: procedural equipment with UsdPhysics joints, one articulation root per machine and semantic labels.
4. `st40_compose`: the root stage with its sublayers and variant sets.
5. `st45_validate`: `nvidia_usd_validate`, `simready-validate`, scene invariants, and a build-twice hash check.

Conventions every layer follows:

- `upAxis = "Z"`, `metersPerUnit = 1.0`, `kilogramsPerUnit = 1.0`, always written explicitly. The fallbacks are Y-up
  and centimetres, and an unauthored value is a silent bug [14][15].
- Coordinates are a local east-north-up frame in metres around a site origin stored in the scene manifest. The glTF
  exporter applies one fixed axis swap, because glTF is +Y up [16].
- Every geometry prim carries a `SemanticsLabelsAPI` class label, with no time samples on label attributes [4][17].
- Small generated layers are written as `.usda` text, in sorted prim order, so they diff and hash cleanly. Heavy
  terrain meshes are `.usdc`.
- The web never parses the full USD stage. A **dual writer** emits USD and glTF from one Pydantic `SceneSpec`, and a
  parity test checks that both carry the same prim names, transforms, vertex counts and labels.

Artefacts it will produce: one `root.usda` per case with its layers, `scene.manifest.json`, the validation reports, and
the glTF / 3D Tiles derivatives baked for the web. Generated USD is never committed; small licence-cleared web
derivatives are ([DEC-0006](../architecture/decisions/DEC-0006-3d-and-simulation-on-static-web.md)).

## Licence and redistribution

TOST-1.0 is Apache-2.0 apart from §6, and its modified-file notice duty applies to changes of OpenUSD itself [11].
PitStudio depends on `usd-core` and never modifies or vendors it. Our own USD files are CC-BY-4.0. NVIDIA sample and
SimReady 3D assets are **not** placed in any committed or published scene, because their redistribution terms are not
open [18].

## Assumptions and limits

- **Kit reads an older USD.** Kit 110 moved to OpenUSD 25.11 [19]. A layer written by `usd-core` 26.8 may use features
  that Kit cannot read, so small layers are written as USDA and every case scene is test-opened in Kit before release.
- **`.usdc` byte determinism is not established.** The hash for binary layers is taken over the flattened text export
  in a fixture test, not over the file bytes.
- `UsdUtils.ComplianceChecker` was removed in 26.08; `usdchecker` now runs on the validation framework [6].
- No imaging: `usd-core` cannot render. Renders come from ovrtx, Isaac Sim or Kit.
