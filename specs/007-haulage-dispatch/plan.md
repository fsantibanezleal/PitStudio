# Plan 007 — Haulage and dispatch (M1–M6)
Spec: ./spec.md

## Summary

1. A thin **adapter** runs the locked `minehaulsim` engine. It replaces the engine's random-stream manager with a
   **counter-based variate source** (Philox4x64-10 + quantile tables) and records a canonical event trace
   (FR-007-01 … FR-007-09).
2. A **TypeScript twin** mirrors the engine's event semantics and reproduces those traces bit for bit (FR-007-10 …
   FR-007-13). The golden traces come from the reference engine, never from the twin.
3. **Dispatchers** are adapters to the engine's policy interface (FR-007-14):
   - the five engine baselines;
   - PitStudio's `min-idle`;
   - the two-stage LP (HiGHS in Python, a small simplex in TypeScript; FR-007-19 … FR-007-22);
   - the learned M4/M5 policies, exported to ONNX (FR-007-31 … FR-007-33).
4. **Learned dispatch** trains in a batched PyTorch environment with time-delta GAE (FR-007-23 … FR-007-28). It is
   judged only in the reference engine on pre-registered paired seeds (FR-007-29, FR-007-30, SC-007-01, SC-007-02).
5. **Root-core** code (`pitstudio.haulage`): route energy over `minephys.haulage`, grade-constrained A\* and the network
   builder, each with a TypeScript port (FR-007-34 … FR-007-40). Every artefact carries the honesty label (FR-007-41).

## Technical context

- **Runtimes and environments:**
  - Python 3.14 in the `pipeline/` environment: `minehaulsim` 0.12.1, torch (cpu/cu126/cu130 extras), onnx and
    onnxruntime, polars, pyarrow;
  - the root environment: numpy, `minephys`, jsonschema, pydantic;
  - Node 24 with Vitest and Playwright for `web/`.
- **Dependencies to add and lock before feature code** (T-007-002; resolved by `uv add`, never hand-pinned):
  - `highspy` → `pipeline/`;
  - `simpy` → the `pipeline/` dev group (test oracle);
  - `scipy` → the `pipeline/` dev group, as a direct dependency (t quantiles and Welch intervals in oracles; it is only
    transitive today);
  - `networkx` → the root dev group (Dijkstra oracle).

  Each must install from wheels on Windows/Python 3.14 and pass an import smoke test.
- **Targets:** local CPU/GPU (training under the runner's `gpu0.compute` lock), CI on CPU (no GPU), GitHub Pages
  (TypeScript engines in web workers; no backend).
- **Code locations:**
  - pipeline package: `pitstudio_pipeline.haulage.{variates, adapter, scenario, kpi, dispatchers, lp}` and
    `pitstudio_pipeline.dispatch.{env, gae, policies, train, evaluate, export}`;
  - root-core: `pitstudio.haulage.{energy, routing, network}`;
  - web: `web/src/engines/{random, des, lp, haulage, routing}/`.

### Tolerances and their justification

| Quantity | Tolerance | Justification |
|---|---|---|
| Philox words, variates, traces, cyclelog, scalar results (Python ↔ TS) | bit pattern | Both languages use IEEE-754 binary64 with correctly rounded +, −, ×, ÷ and no fused multiply-add. With the same operation order and no transcendental calls (FR-007-06), equality is achievable, so anything weaker would hide real divergence. |
| Analytical TypeScript ports vs `minephys` (M1, M6), A\* costs | rtol 1e-12, atol 1e-15 | The library may sum in a different order (NumPy pairwise sums). For ≤ 10³ terms the bound is ≈ n·ε ≈ 2e-13 relative, and 1e-12 leaves a 5× margin. |
| LP optimum / primal / duals (TS vs HiGHS) | rtol 1e-7 / atol 1e-6 | HiGHS defaults to primal and dual feasibility tolerances of 1e-7; a tighter check would test the solver's stopping rule, not the model. |
| DES vs MVA | max(3 SE, 1 %) | 3 SE over 30 independent replications ≈ 99.7 % two-sided coverage for fixed seeds. The 1 % floor covers the initial-transient bias after a 2 h warm-up in 100 h runs (≈ T_c/H ≤ 0.5 %). |
| Deterministic cycle rate | N_T/(H − W) | At most one partial cycle per truck at each window edge. |
| SimPy oracle times | 1e-6 s | The SimPy model adds the same delays, but its clock may accumulate in a different order; 1e-6 s is ≥ 10³ ulp at 8 h. |
| float32 policy invariances | max abs 1e-6 | float32 ε = 1.19e-7, with ≤ 8 accumulated rounding steps on the compared path. |
| Time-delta GAE | rtol 1e-6 (i, iii), 1e-5 (ii) | float32 accumulation over ≤ 512 steps; (ii) adds a float32 `pow` per step. |
| Variate tables | mean rtol 1e-12; variance rtol 1e-2; KS ≤ 2⁻¹¹; empirical KS ≤ 0.007 at 10⁵ draws | The mean is fixed by construction. The piecewise-linear quantile loses a little variance in the outer bins. KS ≤ 1/2¹² + interpolation error. The empirical bound is 1.95/√10⁵ (α = 0.001) + 2⁻¹¹. |
| Environment vs DES (SC-007-04) | 3 % | The tick delay is ≤ Δt/T_c\* ≤ 10 s / 15 min ≈ 1.1 %; the Monte-Carlo noise of the 30-seed means is ≈ 1 %. |
| Export parity | per `thresholds.yaml` `models.onnx_cpu_fp32` | Inherited from the foundation thresholds. |

## Risks and complexity tracking

| Deviation | Why needed | Simpler alternative rejected because |
|---|---|---|
| Substituting the engine's random-stream manager and engine class at construction time (private seam) | Exact Python ↔ TS parity with no transcendental variates | Re-implementing the DES in Python duplicates the engine (rejected in DEC-0013). A recorded variate tape gives parity only for baked seeds, not for live seeds. Guarded by FR-007-02, and moved to a public hook if the engine adds one. |
| A canonical event-kind map pinned to the engine's callback names | Queue-time P90 and a strong event-level trace | The cyclelog alone has no arrival times (spec §8 item 6) |
| A dense simplex in TypeScript | A live LP in the browser | A WASM HiGHS build is unverified for the web budget; A1 LPs have ≤ 64 paths |
| `min-idle` written by PitStudio | Listed on the docs pages, not shipped by the engine | Dropping it would silently narrow the documented baseline set |
| Twin memoisation with round-half-even keys | The reference reuses the first-computed speed per rounded key | Recomputing speeds per segment would diverge in the last bit |
| Golden fixture size (≤ 20 MB in total, each < 2 MB gzip) | The coverage matrix of FR-007-11 | Fewer goldens would leave dispatchers or modes unpinned |
