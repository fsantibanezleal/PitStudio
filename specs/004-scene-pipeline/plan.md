# Plan 004 — Scene pipeline: open studio lane `st10_terrain` → `st45_validate`
Spec: ./spec.md

## Summary
Five CPU-only stages in the `studio/` environment, one Python sub-package each under `pitstudio_studio.scene`:
`terrain` (st10: CRS, units, gridding, harmonic fill, RTIN, tiles, USD terrain layer — FR-004-01…15), `design` (st20:
offsets with shapely, helical ramp, windrows, carving, volumes, road network — FR-004-16…23), `assets` (st30: procedural
fleet with UsdPhysics and labels — FR-004-24…28), `compose` (st40: root stage, scene manifest, scene digest —
FR-004-29…33) and `validate` (st45: validators, invariants, build twice — FR-004-34…39). One generated Pydantic model of
the scene specification (DC-004-01) drives all five; every cross-stage file has a JSON Schema (DC-004-01…08).

## Technical context
Runtime: Python 3.14 in the `studio/` uv project (`uv run --project studio --frozen …`); locked: `usd-core` 26.8,
`usd-validation-nvidia` 1.22.0, `simready-validate` 2026.8.0, `laspy` 2.7.0 (+ `lazrs`), `rasterio` 1.5.2, `pyproj` 3.8.0,
`shapely` 2.1.2, `trimesh` 5.1.1, `zarr` 3.4.0, `numpy` 2.5.3. Node 24 is not involved. Target: local CPU (Windows) and
CI (ubuntu + Windows); no GPU.

Test placement: tests live under the root `tests/` tree (the folders `tools/trace.py` scans), carry
`@pytest.mark.req("<ID>")`, and are collected twice:
- the root job (`uv run pytest -m "not gpu"`) runs the pure-NumPy oracles and schema tests and skips modules that import
  `pxr`, `laspy` or `rasterio` through `pytest.importorskip`;
- a studio CPU job (T-004-002) runs `uv run --project studio --frozen pytest tests -m "not gpu"` with a dev group
  (pytest, hypothesis) added to `studio/pyproject.toml`, and fails if any test file listed for specs 004–006 is skipped
  there, so a skip in the root job can never hide a missing run.

Fixtures (T-004-003): a tiny synthetic DEM GeoTIFF (EPSG:26912 + NAVD88, 129 × 129 cells), the same in US survey feet,
two LAZ 1.4 tiles of 10⁴ points each (ground and non-ground classes), corrupt variants (truncated, bad header, wrong point
count, bad chunk table), a CRS-mismatched copy (NAD83(2011)), and a circular-pit outline; committed under
`tests/fixtures/scene/` (≤ 1 MB in total), generated by a seeded script so they can be rebuilt.

## Design
Data flow: ![File handoffs](../../docs/assets/diagrams/file-handoffs.svg) ·
![Pipeline stages](../../docs/assets/diagrams/pipeline-stages.svg)

```text
SceneSpec (DC-004-01, from recipe params)
  └─ st10 terrain:  open (rasterio/laspy) → CRS + units record → AOI check → crop → ground grid (mean, sorted sum)
                    → nodata rules → harmonic fill → site frame (pyproj, float64 → float32 offsets)
                    → terrain grid (Zarr, DC-004-03) → RTIN per LOD → quadtree tiles + skirts (DC-004-04) → terrain.usdc
  └─ st20 design:   outline (contour or shell) → crest/toe offsets (shapely, mitre) → ramp (arc-length helix) →
                    windrows → design surface → carve min(terrain, design) → volumes + report (DC-004-05) →
                    road network (DC-004-06) → design.usda
  └─ st30 assets:   asset specs → trimesh primitives → USD bodies, joints, MassAPI, CollisionAPI, labels → fleet.usda
  └─ st40 compose:  sublayers + variant sets + physics scene → root.usda, scene.manifest.json (DC-004-02),
                    scene.digest.json (DC-004-08)
  └─ st45 validate: validators + invariants + build twice → validation report (DC-004-07), stage hash
```

Key decisions:
- **RTIN** (Evans et al. 1997 / MARTINI) in NumPy: a tile of (2ᵏ + 1)² samples, error per triangle computed bottom-up,
  refinement until the error ≤ `max_error`; shared tile edges are forced in both neighbours before triangulation
  (FR-004-07).
- **Site frame:** pyproj `Transformer` from the source CRS to the UTM zone of the site origin (`always_xy=True`), origin
  subtraction in float64, then a cast to float32 (FR-004-02).
- **Harmonic fill:** per hole, the 5-point Laplace system with Dirichlet values from valid neighbours, solved by
  `numpy.linalg.solve` (≤ 16 unknowns) (FR-004-05).
- **Ramp:** arc-length parameterisation along the crest polylines with z(s) = z_rim − g·s/100; each bench of height H
  consumes 100·H/g metres of ramp; switchbacks when a perimeter is shorter than that length (FR-004-17).
- **Hashing:** USDA bytes; USDC through `Usd.Stage.Open(layer).ExportToString()` of the flattened layer (FR-004-36).
- **Stage protocol:** each stage is a `python -m pitstudio_studio.scene.<stage>` entry run by the stage helper of spec
  002 (job specification in, `result.json` out). Errors are a small closed enum (`input-corrupt`, `crs-mismatch`,
  `too-much-nodata`, `aoi-invalid`, `aoi-too-large`, `input-path`, `design-infeasible`, `outline-invalid`,
  `asset-invalid`, `compose-invalid`, `path-forbidden`, `waiver-forbidden`, `validation-incomplete`,
  `nondeterministic`, `params-invalid`) written as the prefix of the stage-result message, with `error_class: unknown`.

### Tolerances and their justification
| Quantity | Tolerance | Why |
|---|---|---|
| Mesh vs grid (P-004-01) | `max_error` + 2.5 × 10⁻⁴ m | vertices are float32 site-local offsets with \|z\| ≤ 1000 m: ulp ≈ 6.1 × 10⁻⁵ m, interpolation adds ≤ 2 ulp per coordinate; 2.5 × 10⁻⁴ m covers 4 ulp |
| Site-frame invariances (P-004-03, P-004-04) | atol 1 × 10⁻³ m | float64 transforms (error < 10⁻⁸ m), then float32 storage (≤ 1.2 × 10⁻⁴ m at 1000 m); the margin also absorbs resampling of a shifted grid aligned to the same cells |
| Harmonic fill on planes (P-004-06) | atol 1 × 10⁻⁶ m | float64 dense solve of ≤ 16 unknowns with condition number < 10³: error ≈ 10³ × 2.2 × 10⁻¹⁶ × 500 m ≈ 10⁻¹⁰ m; 10⁻⁶ m leaves room for the float32 inputs |
| Volume identity (P-004-07) | rtol 1 × 10⁻¹² | the two sides sum the same float64 array in different groupings; pairwise summation error ≈ log₂(10⁸) × 2.2 × 10⁻¹⁶ ≈ 6 × 10⁻¹⁵ |
| Analytic pit volume (P-004-07) | Σ_k P_k Δx H and ≤ 1 % | rasterisation misclassifies at most one cell band along each bench edge; on the fixture this bound is ≈ 0.6 % of V_cut |
| Rotation (P-004-08) | Hausdorff ≤ 10⁻⁶ × extent | shapely in float64; mitre offsets of rotated polygons differ only by rounding |
| Ramp grade (FR-004-17, P-004-10) | + 0.1 % grade | sampling at ≤ 1 m on a curved centreline under-resolves curvature; 0.1 % of grade is 1 mm per metre, below any survey precision |
| Bench height and face angle (FR-004-35) | ± 0.5 m, ± 1° | carving on a 1 m grid quantises crest and toe positions to one cell; 0.5 m height and 1° are the resulting worst case at H = 15 m |

## Risks and complexity tracking
| Deviation | Why needed | Simpler alternative rejected because |
|---|---|---|
| Own RTIN instead of a library | no maintained RTIN with Windows / Python 3.14 wheels | `pydelatin`, `quantized-mesh-encoder` have no cp314 Windows wheels; plain grid + decimation has no per-vertex error bound |
| A studio CPU test job besides the root CI job | `pxr`, `laspy`, `rasterio` live only in `studio/` | adding them to the root lock would break the root environment's minimal dependency set |
| Build twice inside the stage | the determinism class `bitwise` must be checked, not declared | comparing against a stored golden would not catch platform-dependent output |
